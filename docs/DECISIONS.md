# KGB_Agent 설계 결정 기록 (ADR)

> 형식: 배경 / 결정 / 대안 / 결과.
> 상태: `확정`(지시서 그대로 또는 영향이 작은 구현 결정) · `승인 필요`(지시서와 다르거나 해석이 갈림 → Phase 0 보고에서 사용자 확인).
> 지시서 PART 2의 D1~D17은 그대로 유효하며 여기서 반복하지 않는다. 아래는 그 위에 추가된 결정이다.

## ADR-001. 지시서 권장 스택 채택 — `확정`
- **배경**: 저장소에는 KGB_Agent와 무관한 소개용 Markdown 3개만 있고 코드·의존성 파일이 없다(지시서 0-1 ②의 "빈 디렉터리"에 해당).
- **결정**: PART 3-2 권장 스택(Next.js App Router + TS, Tailwind + shadcn/ui, FullCalendar, PostgreSQL + Prisma, pg-boss, Anthropic SDK, Vitest + Playwright, Railway)을 채택한다. 단 인증은 ADR-004.
- **대안**: 백엔드 분리(NestJS/FastAPI) — 단일 저장소·단일 언어의 이점을 잃고 인력 대비 복잡도만 증가.
- **결과**: 기존 Markdown 3개는 그대로 둔다. 각 라이브러리 버전은 Phase 1 착수 시점 최신 안정판으로 lockfile에 고정.

## ADR-002. pnpm 워크스페이스 + `@kgb/rules` 패키지 — `확정`
- **배경**: 규칙 엔진은 web·worker가 공유하고 100% 분기 커버리지가 요구된다.
- **결정**: pnpm(컨테이너에 10.28 설치) 워크스페이스. 루트 = Next.js 앱 + worker, `packages/rules` = 순수 TS 패키지(외부 의존성 0, 자체 Vitest 설정과 커버리지 게이트).
- **대안**: npm workspaces(동작은 같으나 설치 속도·엄격한 의존성 격리에서 pnpm 우위), 단일 패키지 내 폴더(커버리지 게이트를 분리하기 어려움).
- **결과**: 규칙 엔진은 DB·시계·네트워크 import 금지(lint 규칙).

## ADR-003. 개발 DB 기동 방식 — `확정`
- **배경**: 지시서는 로컬 Postgres(Docker)를 가정하지만, 현재 클라우드 개발 컨테이너는 Docker 데몬을 쓸 수 없고 PostgreSQL 16이 설치돼 있다.
- **결정**: `docker-compose.yml`(Postgres 16)은 사용자 PC용으로 제공하고, 이 컨테이너에서는 설치된 PG16 클러스터를 기동해 dev/test DB로 쓴다. 두 경우 모두 `DATABASE_URL`만 다르다.
- **결과**: 컨테이너는 휘발성이므로 Phase마다 커밋·푸시. DB 데이터는 시드로 재현 가능해야 한다.

## ADR-004. 인증: Auth.js(v5) Credentials + JWT 세션 — `확정(사용자 결정 N2)`
- **배경**: 지시서 10-3은 ① 초대 링크 가입(72h) ② 로그인 5회/15분 제한 ③ 유휴 7일 만료 ④ 비밀번호 변경 시 전체 세션 무효화를 요구한다. Auth.js의 Credentials(이메일+비밀번호) 방식은 JWT 세션만 지원한다.
- **결정**: 사용자 결정에 따라 **Auth.js v5(`next-auth@5`) Credentials provider + JWT 세션**을 쓴다. 요구사항은 다음처럼 충족한다.
  - ③ 유휴 7일: `session.maxAge = 7일`, `updateAge = 1일`(사용할 때마다 만료 연장 = 슬라이딩 만료).
  - ④ 전체 세션 무효화: `users.session_version` 정수를 JWT에 넣고, `jwt` 콜백에서 DB 값과 다르거나 계정이 `disabled`면 토큰을 무효 처리. 비밀번호 변경 시 `session_version + 1`.
  - ② 시도 제한: `authorize()` 안에서 `login_attempts`(이메일 해시 + IP) 15분 창 5회 검사.
  - ① 초대: Auth.js 범위 밖이므로 `invitations` 테이블 + `/invite/[token]` 페이지로 직접 구현(토큰 해시 저장, 72h, 1회용).
  - 비밀번호 해시: argon2id(`@node-rs/argon2`), 최소 10자.
- **대안**: 자체 DB 세션(Phase 0 제안) — 사용자 결정으로 기각.
- **결과**: `sessions` 테이블은 만들지 않는다. Auth.js v5는 npm 기준 아직 `beta` 태그이므로 버전을 고정(`5.0.0-beta.32`)하고 업그레이드는 별도 검토.

## ADR-005. 작업 큐: pg-boss + `ai_jobs` — `확정`
- **배경**: 지시서는 "ai_jobs 테이블 또는 pg-boss"로 열어 두었다.
- **결정**: 실행 메커니즘(재시도·지수 백오프·지연·cron 스케줄)은 pg-boss, 사용자에게 보여줄 도메인 상태·멱등성 키·비용 대기(`waiting_budget`)는 `ai_jobs`가 담당. `ai_jobs.pgboss_job_id`로 연결.
- **대안**: `ai_jobs` + `FOR UPDATE SKIP LOCKED` 자체 큐 — 의존성은 줄지만 재시도·cron을 직접 구현해야 함.
- **결과**: 별도 인프라(Redis) 없음. 매일 09:00 KST 모니터링·월요일 주간 요약은 pg-boss schedule로 등록.

## ADR-006. Prisma + SQL 보강, 열거형은 `text + CHECK` — `확정`
- **배경**: Prisma 스키마만으로는 부분 고유 인덱스(업무당 lead 1개, pending 제안 dedupe), STORED 생성 컬럼, CHECK 제약을 완전히 표현하지 못한다.
- **결정**: Prisma 마이그레이션 SQL 파일에 해당 DDL을 직접 추가하고, 각 마이그레이션에 되돌리기용 `down.sql`을 둔다. 상태값은 Postgres enum 대신 `text + CHECK`(값 추가가 가벼운 마이그레이션) + TS 쪽 zod enum으로 이중 검증.
- **대안**: Drizzle(SQL 표현력은 높으나 지시서 권장과 다름).
- **결과**: 스키마 드리프트를 막기 위해 통합 테스트에서 제약 위반이 실제로 거부되는지 확인한다.

## ADR-007. `effective_progress`는 STORED 생성 컬럼 — `확정`
- **결정**: `GENERATED ALWAYS AS (CASE WHEN is_completed THEN 100 ELSE COALESCE(manual_progress, ai_progress, 0) END) STORED`. Prisma 모델에서는 읽기 전용(선택 필드, 쓰기 금지 lint). 같은 공식을 `@kgb/rules.effectiveProgress()`로도 제공해 UI 낙관적 업데이트에 쓰고, 두 구현 일치 테스트를 둔다.
- **결과**: "직접 수정 금지"(4-3)가 DB 수준에서 보장됨. 완료 해제 시 manual/ai 값이 남아 있으므로 "직전 값 복귀"(D3)가 자동 성립.

## ADR-008. `references` 물리 테이블명 → `reference_items` — `확정`
- **배경**: `references`는 SQL 예약어라 원시 SQL·리포트 쿼리마다 따옴표가 필요해 실수 위험이 있다.
- **결정**: 의미·필드는 지시서 그대로, 물리 테이블명만 `reference_items`(Prisma 모델명 `ReferenceItem`).

## ADR-009. 규칙 엔진의 날짜 표현 — `확정`
- **결정**: 규칙 엔진 입·출력은 `YYYY-MM-DD` 문자열이며 내부적으로 "에포크 일수" 정수로만 계산한다(시간대 개념 없음). "오늘"은 호출 측이 `Asia/Seoul` 기준으로 계산해 인자로 넘긴다. 휴일은 설정의 날짜 목록.
- **결과**: 실행 서버의 TZ와 무관하게 같은 입력 → 같은 일정(D16). 테스트에서 "오늘"을 고정하기 쉬움.

## ADR-010. LLM 공급자 추상화와 모델 설정 — `확정`
- **결정**: `lib/ai/provider.ts` 인터페이스 아래 `anthropic`/`mock` 구현. 모델명은 `LLM_MODEL`(전역)과 `LLM_MODEL_A1`~`A7`(선택 덮어쓰기). 기본 권장: 분석·제안·평가·레퍼런스(A1·A2·A5·A6)는 상위 모델, 짧은 요약·문구(A4 안내문·A7 요약)는 경량 모델로 비용 절감. 실제 모델 ID·단가는 Phase 5 착수 시 공식 문서로 확인해 `.env.example` 주석과 비용 추정 표에 반영.
- **결과**: `mock`은 픽스처 JSON 기반 결정적 응답. `APP_ENV ∈ {staging, production}`에서 `AI_PROVIDER=mock`이면 서버·워커 시작 거부.

## ADR-011. 학생회장 주관 업무는 만들지 않음 — `확정(사용자 결정 N3)`
- **배경**: 표준 업무 중 `PRES_SUBMIT_SCHOOL`(주관: 학생회장)은 5개 국서가 아닌 회장이 주관하고, `FIN_BUDGET_RANGE`·`PLN_APPROVAL`은 학생회장이 협조자다.
- **결정**: 회장단 국서 행을 추가하지 않는다. 국서는 5개만 존재한다.
  - `PRES_SUBMIT_SCHOOL`은 **업무(task)로 생성하지 않고**, 교비 사업에 규칙 엔진이 만드는 **일정 마일스톤**(`schedule_events`, kind=`milestone`, origin=`rule`, 제목 "행정실 송부 마감(D-21)")으로만 표시한다. 이 날짜는 여전히 `VENDOR_CONFIRM`(≤ D-21-7) 등 역산의 고정 앵커로 쓰인다(T5의 "행정실 송부 = 11-19"는 이 마일스톤 날짜로 검증).
  - 5-6의 "D-21 행정실 송부 미완료 → critical 알림"은 업무가 없으므로 "행정실 송부 마감 D-7/D-3/D-1 리마인더"(회장·기획국장 대상)로 대체한다.
  - 표준 업무의 협조 국서 목록에서 "학생회장"은 제외한다(기획안 결재는 업무가 아니라 기획안 모듈의 결재 기능으로 처리).
- **결과**: 진척도 막대는 지시서대로 5개 국서 구간만 가진다.

## ADR-012. 일정의 단일 원천과 미승인 제안 표시(D2 해석) — `확정`
- **배경 ①**: 지시서는 `tasks.due_date`와 `schedule_events(kind=deadline, task_id)`, `projects.event_start`와 `schedule_events(kind=event_day)`를 모두 정의해 같은 날짜가 두 곳에 저장될 수 있다(동기화 문제 — D10이 업무 복제를 금지한 것과 같은 이유).
- **배경 ②**: D2는 "AI 제안 마감을 즉시 캘린더·투두리스트에 표시"를 요구하지만, 6-1·PART 7은 업무가 **승인 시점에** 생성된다고 한다.
- **결정(안)**: ① 캘린더 피드는 `projects`(행사일) + `tasks`(마감) + `schedule_events`(사업·업무에 묶이지 않은 마일스톤·회의·사용자 일정)를 조회 시점에 합친다. 날짜 복제 없음. ② `pending` 제안의 마감은 읽기 전용 "고스트 항목"(점선·연한 색·"AI 제안" 배지·"승인" 버튼)으로 같은 피드에 섞어 보여준다. 승인 전에는 `tasks`에 아무것도 쓰지 않는다.
- **결과**: D2의 편의성과 "AI는 확정 데이터를 쓰지 않는다" 원칙을 동시에 만족. 드래그로 고스트 항목 날짜를 바꾸면 "수정 후 승인(edited_approved)"으로 처리.

## ADR-014. 마감 역산 알고리즘의 세부 해석 — `확정`
지시서 5-2·5-3을 구현 가능한 수준으로 확정한다. 모든 해석은 규칙 엔진 단위 테스트로 고정한다.
1. **소요일 규칙**: 소요 d일, 마감 LF인 업무의 최종 착수일 = LF − d. 착수 가능일 ES부터 d일 후가 ES + d.
2. **후속 업무가 없는 행사 전 업무**(예: `SEC_CONTACT`, `SEC_PARTNER_LIST`)의 LF = D−1.
3. **행사 후 업무**는 역산이 아니라 순방향 앵커: `OPS_EXECUTE` = D(행사 종료일), `OPS_EVIDENCE` = 종료일 + `EVIDENCE_PHOTO_GRACE_DAYS`, `FIN_EVIDENCE` = 종료일 + 7.
4. **의존 유형별 일정 의미**: `finish_to_start`·`approval_required` = 선행 완료 후 착수. `draft_ok` = 선행 업무와 **겹쳐 진행 가능**(착수는 선행 착수 이후, 완료는 선행 완료 이후).
5. **`draft_ok`와 Q7의 관계**: 템플릿 표에 `(draft_ok)`로 적힌 의존(FIN_BUDGET_RANGE→PLN_DRAFT, PLN_DRAFT→SEC_PARTNER_LIST)은 본래 허용. 템플릿상 `approval_required`인 의존(예: SEC_PROPOSAL의 PLN_APPROVAL)을 초안 기준으로 풀어 주는 것이 D7·Q7의 "초안 기반 선착수"이며 국장이 업무별로 허용(기본 불허).
6. **행정실 송부 마일스톤(ADR-011)의 외부업체 선행**: "(외부업체 시) SEC_CONTACT 또는 VENDOR_CONFIRM"은 **VENDOR_CONFIRM**으로 해석한다(SEC_CONTACT는 제휴 문의로, 행정실 송부의 필수 선행이 아님). 마일스톤 자체는 D-21 고정.
7. **주말·휴일 보정**은 고정 앵커에도 적용(예: D−21이 토요일이면 금요일까지 송부) — "늦어도" 조건을 지키는 방향(더 이른 날)으로만 보정.
8. **`FIN_PURCHASE` 소요일**: 지시서에 없음 → 기본 1일.
9. **홍보 등급 미정 시 `PRO_MAKE` 소요**: 등급(PRO_TIER) 결정 전에는 회의록에서 추정된 등급, 추정도 없으면 **저비용**으로 계산하고, 등급 확정 시 재계산. 저비용 제작 소요는 사용자 결정(N5)에 따라 **4일**(지시서 5-4의 "제작 4일 + 인쇄 3일"을 대체).
10. **최소 소요일**(infeasible 대안 (a)): 지시서에 값이 없음 → 기본 `ceil(기본 소요 / 2)`, 설정에서 수정 → 미결정 N6.
11. **`SEC_MONITOR`**(주 1회 상시)는 단일 마감 대신 반복 일정으로 표현하고 역산에서 제외.

**T5 사전 계산 결과(참고)** — 행사일 2026-12-10(목), 오늘 2026-10-31(토), 교비 + 외부업체, 기본 소요일:
행정실 송부 마일스톤 11-19(목) ✅, `VENDOR_CONFIRM` ≤ 11-12(목) ✅, `PLN_APPROVAL` ≤ 11-05(목) → 업체 컨택(11-05~)보다 앞섬 ✅.
다만 그 앞의 `PLN_DRAFT`(≤ 11-02(월), 5일)·`FIN_BUDGET_RANGE`(draft_ok 겹침 규칙상 ≤ 10-31 → 주말 보정 10-30(금), 3일)는 오늘 기준 착수해도 마감을 넘기므로 **infeasible**로 표시된다. T5의 세 합격 조건은 충족되며, 이는 "40일 남은 교비+외부업체 행사"가 실제로 빠듯하다는 정상적인 경고다(자동 압축하지 않고 대안 제시 — D6).

## ADR-015. 색 접근성 보완 — `확정(기본값 N7)`
Phase 0에서 지시서 9-1·9-2 색 조합을 WCAG 2.x 공식으로 미리 계산했다.
- **통과(본문 4.5:1 이상)**: 국서 칩·막대 위 글자색 전 조합(최저 홍보국 `#6B2E1A` on `#E19E86` = 4.65), 흰 글자 on 사무국(10.80)·집행국(5.77), 본문·보조 텍스트, 성공·위험·정보 중립 색.
- **미달 ①**: 경고 `#B7791F` 흰 배경 위 글자 = 3.64 → 경고 **글자색만** `#8A5A12`(5.91)로 조정하고 `#B7791F`는 아이콘·테두리에만 사용(9-1 "글자색만 조정" 원칙과 동일).
- **미달 ② (비텍스트 대비)**: 진척도 막대의 채움 vs 남은 부분 대비가 기획국 1.16, 재정국 1.62, 홍보국 1.84로 매우 낮아 "완료된 비율"이 눈으로 구분되기 어렵다(사무국 7.76·집행국 4.51은 양호). 국서 base·track 색은 지시서상 변경 금지.
  → 결정(안): 색은 그대로 두고 **채움 끝에 국서 ink 색 2px 경계선**을 그리고, %를 항상 숫자로 병기한다(9-3과 일치). 기획국은 지시서대로 채움에 `#D9BBA6` 1px 테두리도 적용.
- **결과**: Phase 1의 색 대비 자동 테스트는 위 조합을 모두 검사하고, 비텍스트 항목은 "경계선 보완 필요" 목록으로 관리. 미결정 N7.

## ADR-016. 역할 체계: 부회장 없음, 국장 = 회장과 동등 — `확정(사용자 결정 N10)`
- **배경**: 이 학생회에는 부회장이 없고, 회장 다음이 바로 국서별 국장이다.
- **결정**: 역할은 `admin`, `president`, `head`, `member` 4개. `vice_president`는 만들지 않는다. **`head`(국장)는 `president`와 동일한 권한**을 가진다(지시서 10-2의 "자기 국서만" 제한 없음 — AI 제안 승인 전체, 사업 생성·일정 확정·취소, 기획안 결재, 예결산 편집, 인적사항 편집, 설정·회원·파라미터 포함). 백업만 `admin` 전용.
- **결과**: 권한 매트릭스(`lib/auth/can.ts`)는 사실상 3단계: admin ⊇ president = head ⊋ member. `member` 권한은 지시서 10-2 그대로(Q4·Q5 기본값 포함). Q11은 "부회장 없음"으로 종결.

## ADR-017. 국원의 마감 변경 요청 — `확정`
- **배경**: Q5 기본값 "국원은 마감 변경 **요청**만, 국장 승인".
- **결정**: 별도 테이블을 만들지 않고 `proposals(kind = deadline, source_type = manual, target_id = task)`로 저장해 기존 검토 화면·승인 트랜잭션을 그대로 쓴다. 해당 국서 국장·회장에게 알림.

## ADR-018. 개인정보 최소화 세부 — `확정`
- `login_attempts`의 이메일은 해시로 저장. `activity_logs.diff`는 `member_profiles`·`contact_rows`의 전화·이메일·학번 필드를 `***`로 마스킹. AI 입력 조립 함수는 두 테이블을 import할 수 없게 모듈 경계를 둔다. 회의록 본문의 전화번호·이메일·학번 패턴은 LLM 전송 전 마스킹(원문은 DB에만 보관).
- `activity_logs.ip`는 보안 감사 목적으로만 보관하고 보존 기간(기본 90일) 후 정리 — 보존 기간은 운영 전환 시 확정.

## ADR-019. GitHub 저장소 그대로 배포 — `확정(사용자 결정 N1)`
- **배경**: 사용자는 이 저장소를 GitHub에 올리고, **코드 그대로 바로 웹사이트를 만들 수 있기**를 원한다. 당분간 사용자 1인만 보는 개인용 사이트(= 지시서의 스테이징 역할)다.
- **결정**:
  - 앱 코드는 **저장소 루트**에 둔다(기존 Markdown 3개 유지).
  - 배포 기본안을 **Render Blueprint**(`render.yaml`)로 한다: GitHub 저장소를 연결하면 web 서비스 + 관리형 Postgres가 한 번에 생성되고, 빌드 시 마이그레이션·초기 관리자 생성이 자동 실행된다. 푸시하면 자동 재배포. (Railway도 같은 Dockerfile·명령으로 배포 가능하도록 `Dockerfile` 함께 제공.)
  - 개인용 1인 사이트 비용을 줄이기 위해 **워커를 web 프로세스 안에서 실행하는 모드**(`WORKER_MODE=inline`, 기본값)를 지원한다. 사용량이 늘면 `WORKER_MODE=separate` + 별도 worker 서비스로 전환.
  - 지시서 Q8(Railway)은 "Render 기본, Railway 대안"으로 변경.
- **대안**: Railway 기본 — DB를 대시보드에서 수동 추가해야 해서 "그대로 바로"에 덜 맞음. Vercel — 장시간 워커 실행 제약.
- **결과**: 배포는 사용자 계정에서만 가능하므로 이 개발 환경에서는 `next build` + `next start`(production 모드)로 검증하고, 실제 배포 확인은 사용자에게 요청한다. 정확한 요금은 Render 요금표에서 확인 필요(무료 플랜은 슬립·DB 보존 기간 제약이 있음).

## ADR-020. 파일 저장소 드라이버에 `db` 추가 — `확정`
- **배경**: Render·Railway의 컨테이너 디스크는 재배포 시 사라진다. S3 호환 버킷은 별도 계정·키가 필요해 "그대로 바로 배포"를 어렵게 한다.
- **결정**: `lib/storage`에 `local`(개발) / **`db`**(Postgres `stored_files` 테이블에 bytea 저장, 개인용 배포 기본값) / `s3`(운영 확장) 드라이버를 둔다. 다운로드는 항상 서버를 거치는 서명 URL(10분 만료, HMAC)로 제공해 드라이버와 무관하게 같은 보안 규칙을 적용.
- **결과**: 업로드 상한 50MB는 유지. 사용량이 커지면 `STORAGE_DRIVER=s3`로 전환(데이터 이전 스크립트는 운영 전환 시 작성). Phase 2에서 구현.

## ADR-021. AI 공급자 `none` 모드 — `확정`
- **배경**: 지시서 3-4는 staging/production에서 `mock` 사용 시 서버 시작 거부를 요구한다. 그런데 개인용 사이트를 API 키 없이 먼저 띄워 볼 수 있어야 한다.
- **결정**: `AI_PROVIDER ∈ {anthropic, mock, none}`. `none`(키 없음)은 AI 기능만 끄고 "AI 일시 사용 불가"를 표시하며 수동 기능은 정상 동작(T25와 같은 동작). staging/production에서 `mock`은 여전히 시작 거부.
